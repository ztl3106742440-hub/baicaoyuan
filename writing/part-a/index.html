PART A · APPLICATION WRITING

小作文不是套壳文学，
是把事情说完整。

01

START HERE

认识小作文：10 分首先看任务完成

评分核心是完成交际任务、信息完整、格式正确、语气得体。题目叫“回复”并不意味着它是一种独立纸面体裁——回复仍可能是一封邮件。标签不是护身符，题干才是老板。

邮件 / 书信

面向明确收件人

称呼、目的、必答信息和礼貌结尾相互配合，语气随关系变化。

通知 / 告示

面向一组读者

标题、时间、地点、对象、报名或联系信息应清楚，不硬套书信落款。

判断原则不要只看题型名称；先回答“我在对谁、为了什么、必须说哪几件事”。
02

DECIDE BEFORE DRAFTING

先判题，再写：五步审题

  1. 收信人同学、老师、机构或公众？
  2. 写作目的邀请、建议、回复、说明还是通知？
  3. 必答任务把题干动词拆成可核对清单。
  4. 语气正式程度与关系匹配。
  5. 格式称呼、正文、落款或通知要素。
点击展开 · 典型陷阱
  • 写了漂亮寒暄，却漏掉题干要求的具体安排。
  • 把“回复说明”误当成一种与邮件并列的固定格式。
  • 题目没给时间地点，却从背过的范文里整段搬运。
  • 为了显得正式，把朋友邮件写成外交照会。
03

TWO-DIMENSION MAP

功能与体裁要交叉判断

功能邮件 / 书信通知 / 告示
邀请与安排说明活动、时间与回应方式面向群体发布安排
建议与推荐依据对方需要给可操作建议通常不是首选体裁
回复与说明回应来信并补齐必答信息用于公开澄清时才成立
通知与招募可向个人发送，但仍属邮件时间、地点、资格、报名方式
询问 / 道歉 / 感谢围绕具体关系与事件仅在公开场景按题意使用

CORE TEMPLATES

四组核心功能母版

邀请与安排、建议与推荐、回复与说明、通知与招募。正式教材到位后，每个槽位都可单独看中文提示、填入示例并恢复；数据不是写进可执行 HTML，而是按纯文本渲染。

05

PROMPTS · ANNOTATED

代表题与逐句精讲

先看可核实的题面摘要和任务点，再自己审题、列提纲，最后揭晓原创教学示范。逐句呈现英文、必要难词、译意与短评；复杂语法和风险默认折叠，不再把全文复制两遍。

06

FUNCTION LIBRARY

功能句补充库

按称呼、目的、细节、建议、礼貌结尾、通知时间地点与报名方式调用。每条先给安全版；升级版只有在真正提高表达且不增加错误风险时才值得展开。
